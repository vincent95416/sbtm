# 人工補充地圖

此 skill 不操作瀏覽器、不碰 Playwright MCP。只負責代 QA 編輯既有頁面檔，用「人補 / 日期」格式標記被人動過的條目（操作表以證據欄、條列段以尾綴）。

## 開始前
1. 解析 QA 的意圖，拆成具體動作：新增 / 修改 / 刪除；可能跨多條目、多段落
2. 確認位置：<模組> / <頁面>；缺任一先問
3. 讀 docs/product-map.md 與目標頁面檔；不讀其他模組
4. 目標頁面檔不存在：
   - 若 QA 要補的是現場觀察結果 → 建議改跑 map-product 建骨架
   - 若 QA 明確要本 skill 建骨架 → 建最小骨架（header 欄位 + 三個空段落）

## 可動範圍
- 頁面檔內的三個段落：**操作表** / **相關網路請求** / **資料驅動內容**
- **不碰** `docs/product-map.md`（索引仍由 map-product 寫；若 QA 補的是全站共用的資料驅動項目，提示他手改索引或等下輪 map-product）
- **不碰** 頁面檔的 header 欄位（路徑、入口、角色）—— 這些由 map-product 或手改

## 動作規則

三段的「人補」標記方式不同：
- **操作表（表格段）**：證據欄填 `人補 / <YYYY-MM-DD>`
- **相關網路請求、資料驅動內容（條列段）**：條列文字後加尾綴 `［人補 / <YYYY-MM-DD>］`（全形方括號，與行內 `（）` 區別）

### 新增
- 加在對應段落末尾
- 操作表的新增：欄位 schema 同 map-product/SKILL.md
  - 項目、類型、去向：規則同 map-product/SKILL.md
  - 狀態：QA 指定；未指定時預設「待確認」
  - 證據：`人補 / <YYYY-MM-DD>`
- 條列段的新增：依該段原本的格式寫，末尾加 `［人補 / <YYYY-MM-DD>］`

### 修改
- 可改任何欄位或條列文字
- 操作表：
  - **狀態**：QA 每次指定（維持原值 / 改為指定值）；**未指定時保持原狀態**，skill 必問，不替 QA 判斷
  - **證據**：改為 `人補 / <YYYY-MM-DD>`（不論原本是 AI 的 env/ver/role/date 還是先前的「人補 /」）
- 條列段：
  - 改完文字後，確保行尾有 `［人補 / <YYYY-MM-DD>］`；若已存在就就地更新日期

### 刪除
- 直接刪整列（表格列或條列），不留 tombstone
- 歷史由 git log 保存

## 禁止
- 寫入帳號、密碼、個資或任何測試憑證
- 寫入業務規則、欄位驗證、計算邏輯（CLAUDE.md 共通規則 #8）
- 未經 QA 確認就落檔
- 碰 docs/product-map.md

## Checkpoint 時機
依 CLAUDE.md 的 checkpoint 格式。

| 時機 | 預設 |
|---|---|
| 解析 QA 意圖時發現模糊、不確定 | 需裁決才能繼續（先問清楚再拆變更清單） |
| 列出變更清單 preview 後 | 需裁決才能繼續 |
| 若 QA 要求建新頁面檔骨架前 | 需裁決才能繼續 |
| 落檔完成 | 不需介入就繼續 |

## 變更清單 preview 格式

跨段落的意圖一次整包 preview，用下列表格：

| # | 段落 | 動作 | 條目 | before | after |
|---|---|---|---|---|---|

- 段落只能是：操作表 / 相關網路請求 / 資料驅動內容
- 動作只能是：新增 / 修改 / 刪除
- before/after 寫關鍵內容；新增的 before 寫「—」、刪除的 after 寫「—」
- 若 preview 有「修改」動作，額外附狀態處理子表，QA 逐條指定維持或改：

| # | 條目 | 原狀態 | QA 指定 |
|---|---|---|---|

## 結束時輸出
- 落檔的變更清單（6 欄表格）
- 若建了新頁面檔骨架，列出路徑
- 索引（docs/product-map.md）是否需要跟進（例如模組從「未探索」改「待確認」、全站共用資料驅動項目要新增一條）—— 不自動改，由 QA 判定
