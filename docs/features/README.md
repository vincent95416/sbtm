# docs/features/

> 各模組 / 頁面的細節文件。由 `map-product` skill 探索時建立；QA 補 / 改 / 刪走 `/annotate-map` skill，不要直接編輯 md 檔。

## 目錄規則
- 一個模組一個子目錄：`docs/features/<module>/`
- 每個頁面一個檔：`docs/features/<module>/<page>.md`
- 檔名用 kebab-case（例：`checkout/payment.md`、`member/profile.md`）

## 檔案範本
以 `map-product/SKILL.md` 的「格式」段落為準，不要在此另立一份。範本摘要：

```markdown
# <頁面名稱>
- 路徑：<URL pattern>
- 入口：<從哪裡進來>
- 角色：<可見此頁的角色；其他角色的行為>

## 操作
| 項目 | 類型 | 去向 | 狀態 | 證據 |
|---|---|---|---|---|

## 相關網路請求
- <時機>：<METHOD> <URL> → <status>（<說明>）

## 資料驅動內容
- <來自 CMS 或測試資料的欄位；不一致時優先懷疑環境資料>

## 排除（可選；由 annotate-map 刪除動作維護，map-product 不寫入）
- <項目名>｜<原因簡述>（人補 / <日期>）
```

格式規則（詳見 `map-product/SKILL.md`）：
- 「類型」只能是：連結 / 按鈕 / 輸入 / 顯示 / 送出動作（未執行） / 送出動作（已執行）
- 「去向」為推測時，必須加註「（推測）」；無去向填「—」
- 「相關網路請求」只記功能性請求，時機限：載入時 / 操作觸發 / 定時 / 其他
- 操作表證據欄格式：AI 寫入用「環境 / 版本 / 角色 / 日期」；annotate-map 寫入用「人補 / 日期」
- 相關網路請求、資料驅動內容的條列段：annotate-map 編輯過的尾綴「［人補 / 日期］」；AI 寫入的不加尾綴
- annotate-map 可編輯的段落：操作表、相關網路請求、資料驅動內容、header 角色、排除；不碰 header 的路徑與入口、不碰 docs/product-map.md
- 排除段落：由 annotate-map 的刪除動作維護（動機 B「不該在這頁」或 D「隱藏功能」會把條目搬到此段），map-product 探索時讀此段並跳過匹配項
- 不要新增其他段落（允許的段落固定為：操作、相關網路請求、資料驅動內容、排除）；證據只保留最新一筆，歷史由檔案內的「排除」/「人補」痕跡與 git 保存

## 原則
1. **顆粒度是「頁面與流程」**，只記錄導航資訊，不記錄業務規則、欄位驗證、計算邏輯。
2. **送出類操作只記錄「會做什麼」，不實際執行。**
3. **狀態欄只有「待確認」一值** —— 「AI 寫的、未經人改」的永久屬性，不是待辦，不需要去「處理」。人經手走 `/annotate-map`，痕跡留在證據欄 / 條列尾綴（「人補 / 日期」），不改狀態。
4. **單檔超過 300 行時拆分**，原檔只留摘要與連結。
