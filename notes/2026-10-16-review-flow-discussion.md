# 討論筆記：review 流程設計疑慮

- 日期：2026-10-16
- 類型：流程設計討論（非探索報告，非地圖）
- 狀態：**暫存，待下次回顧後決定方向**
- 相關檔案：CLAUDE.md 共通規則 #4、#8；`.claude/skills/map-product/SKILL.md`

---

## 原始疑問（by QA）

> review 的動作都是去找到待確認 > 已確認嗎？這樣好像跟原本工具想要的方向有點背道而馳，而且未接觸過的同仁還可能會把他已知的事情直接改寫 md 檔，造成探索混亂等等。

---

## 問題拆解

### 1. 「review = 待確認 → 已確認」淪為背書

目前流程預設：
```
AI 寫入「待確認」→ QA 看 → 改成「已確認」
```

隱性假設都站不住腳：

| 假設 | 實際上 |
|---|---|
| QA 真的會逐條驗證 | 20 條「待確認」整批打勾（確認偏誤 + 審美疲勞） |
| QA 的角色是「驗證 AI」 | QA 本身是**產品知識持有者**，不只是驗證者 |
| AI 不會寫錯 | AI 會誤判，但 skill 格式沒有「否決」「存疑」「人工補充」語義 |

### 2. 未接觸同仁想直接改 docs 的誘惑

情境：新 QA 加入 → 他知道「個人設置裡的『限紅返水』是會員 VIP 等級設定」→ 看到 docs 標「未探索」→ 自然反應是**直接編輯 md 檔**。

但 CLAUDE.md 共通規則 #4「docs/ 只能透過 map-product 修改」導致：

- 同仁的既有知識**沒有合法入口**進入 docs
- 遵守規則 → 得跑 map-product 問 AI 幫忙，很笨
- 不遵守規則 → AI 下輪 map-product 時「發現不一致」會覆蓋人寫的

**無論走哪條都卡**。

---

## 建議改善方案（4 個方向，可組合）

### 方向 A：擴大「狀態」欄的語義

從只有「待確認 / 已確認」，變成：

| 狀態 | 意義 | 誰寫 |
|---|---|---|
| 待確認 | AI 剛寫入，未驗證 | AI |
| 已確認 | 已驗證對 | 人 |
| 否決 | AI 寫錯，實際上不是這樣 | 人 |
| 人工補充 | 不是 AI 探索到的，是人直接寫的 | 人 |
| 存疑 | 人看了也不確定 | 人 |

**解決**：「否決」和「人工補充」有地方放。
**沒解決**：「人直接改 docs」的流程問題。

### 方向 B：讓人也走 skill（新增 `annotate-map`）

新 skill 專門給人用：
- 讓人加「人工補充」條目（自動標上作者、日期）
- 讓人把 AI 的條目「否決」「補充」「修改」
- 走這 skill 就有 trace，不會亂改

**人的入口變成**：
```
我知道這個功能怎樣 → /annotate-map 補到 docs/
```

**解決**：給人一條合法的 docs 寫入路徑；避免「直接改 md 檔」的衝動。

### 方向 C：區分「探索結果」vs「規格知識」

目前 docs/ 混了兩種：
- **探索結果**：AI 走過 UI 看到的（會動態變）
- **規格知識**：人本來就知道的業務邏輯（相對穩定）

分成兩個檔案或兩個段落：
- `docs/features/<module>/<feature>.md` → 導航結構（AI 寫 / 人 review）
- `docs/features/<module>/<feature>.rules.md` → 業務規則（人寫 / AI 讀但不改）

**衝突**：跟 CLAUDE.md 共通規則 #8「地圖只記導航資訊，不記業務規則」直接衝突，得先決定業務規則要不要納入 docs/、放哪、誰寫、怎麼跟地圖連結。

### 方向 D：改 review 流程，讓它更像 PR review

Review 不是「改 md」，而是「每個待確認項目**附上一條回應**」：
- 「確認：10/16 QA Vincent 驗過」
- 「否決：這條其實是 X，不是 Y」
- 「補充：這頁還有個 Z，AI 沒看到」

QA 的動作是**留痕**，不是改內容。改內容仍走 map-product。

**要有工具支援**：commit message / 外部表格 / 專門的 review 欄位，有點重。

---

## AI 的直覺（不是結論）

- **A（擴大狀態語義）** 幾乎必做，否則 QA 連「否決」都沒地方寫
- **B（新 skill `annotate-map`）** 解決「人想直接改」的誘惑
- **C（規格知識分離）** 比較大，不急
- **D（PR 式 review）** 滿好，但要有工具支援

**最輕量的起手**：A + B 一起做。
